# PolicyDesk

**Company policies, clear answers.**

PolicyDesk is an internal policy assistant for small teams. Employees can ask about
leave, travel, pay, benefits, career progression, reporting relationships, and information
handling. Answers include retrieved policy sources, and CLI conversations retain session history.

## Features

- Policy search over company text documents.
- Streamed answers generated by Qwen Plus with retrieved policy context.
- Local HuggingFace embeddings and persistent MongoDB, Chroma, and Redis storage.
- Named conversation sessions with saved history.
- A local web demo with example questions, streamed answers, and policy excerpts.

## Policy library

The eight English policy documents in `data/` describe one fictional company. The
amounts, approval rules, organization structure, and salary bands are sample business
data rather than real personnel records.

| File | Coverage |
| --- | --- |
| `leave_policy.txt` | Leave requests, approval thresholds, emergencies, and handovers |
| `travel_policy.txt` | Travel approval, lodging limits, invoices, and reimbursement deadlines |
| `overtime_policy.txt` | Working hours, cumulative approvals, time records, and compensatory time |
| `salary_policy.txt` | Pay dates, L1-L5 salary bands, salary reviews, and payroll corrections |
| `promotion_policy.txt` | Career levels, evidence, review windows, panels, and appeals |
| `employee_benefits_policy.txt` | Learning budgets, wellbeing, health checks, and equipment claims |
| `information_classification_policy.txt` | Public, Internal, Confidential, and Restricted handling rules |
| `company_hierarchy_policy.txt` | Departments, reporting lines, management roles, and delegation |

Example questions for the expanded library:

- Who approves overtime if my weekly total increases from six to nine hours?
- When is salary paid if the twenty-fifth falls on a weekend?
- What evidence do I need for promotion to L3?
- What is the annual learning budget, and when must I submit a benefit claim?
- Does an L5 grade automatically allow access to Restricted information?
- Does a project lead approve my leave, or does my direct manager approve it?

## Project status and roadmap

PolicyDesk is currently a simplified version built around a basic RAG workflow.
Over the next two months, we plan to extend it with:

- Pre-retrieval processing to prepare and refine queries before retrieval.
- Hybrid retrieval to combine keyword search with vector similarity search.
- Post-retrieval processing to filter and rerank retrieved context before answer generation.

These capabilities are planned updates and are not included in the current version.

## Requirements

- Python 3.11.
- Docker with Compose.
- A DashScope API key with access to `qwen-plus`.
- Network access for dependency installation and the first embedding-model download,
  or an existing local copy of `BAAI/bge-large-zh-v1.5`.

## Installation and configuration

Run from the PolicyDesk project directory:

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows, activate the environment with `.venv\Scripts\Activate.ps1` in PowerShell.
If an environment already exists, activate it and install the dependencies as needed.

Create `.env` from `.env.example` for a new installation. If `.env` already exists,
edit it instead of overwriting its settings.

```bash
cp .env.example .env
```

Obtain a key through the [official Model Studio API key guide](https://help.aliyun.com/zh/model-studio/get-api-key)
and configure:

```dotenv
DASHSCOPE_API_KEY=your_dashscope_api_key
EMBEDDING_MODEL=BAAI/bge-large-zh-v1.5
KB_NAME=policydesk_v1
MONGO_DB=policydesk
```

The DashScope adapter uses its default China (Beijing) endpoint. Use a key valid for
that region. `EMBEDDING_MODEL` also accepts an existing local model directory.
Shell environment variables take precedence over `.env`; real keys belong in local
configuration, which is excluded from Git.

Start the database services:

```bash
docker compose up -d --wait
docker compose ps
```

MongoDB, Redis, and Chroma use localhost ports 27028, 6389, and 8018 respectively.
Named Docker volumes retain their data between restarts.

## Usage

Place company policies as UTF-8 `.txt` files in `data/`.

| Command | Purpose |
| --- | --- |
| `python main.py preview` | Inspect loaded policy text without model calls or databases |
| `python main.py build` | Create the knowledge base once for the configured namespace |
| `python main.py ask "Who approves extended leave?"` | Ask a question using the saved knowledge base |
| `python main.py chat --session employee-travel` | Open or restore a named conversation |

Enter `/exit` to leave chat. Reuse a session name to restore its history, or choose
another name for a separate conversation.

Existing knowledge bases are reused for questions and chat. To index changed policies
or a different embedding model, choose a new `KB_NAME` and run `build` for that
namespace. Use a new namespace after an interrupted build as well.

Retrieved filenames and similarity scores identify supporting material; they are not
verified sentence-level citations or confidence scores.

## Web demo

After installing the dependencies, configuring `.env`, starting the databases, and
building the knowledge base as described above, launch the interface:

```bash
python -m streamlit run app.py
```

Open [PolicyDesk locally](http://127.0.0.1:8501). Choose an example question or enter
your own, then select **Ask PolicyDesk**. Answers stream into the page, with
expandable retrieved excerpts and similarity scores underneath. The sidebar shows
the source policy files for reference.

The page can open without a model call; models and the saved index load on the first
submitted question. The first question may take longer while the embedding model
loads or downloads. Each question is independent; use CLI `chat` for persistent
conversations. Web results are temporary display state and are cleared on a browser
reload. The interface uses the same configured database index as the CLI, so changed
policy files require a new `KB_NAME` and `python main.py build` before they appear in
answers. Restart the web app after changing `.env` or rebuilding the index.

The demo binds to localhost and has no user authentication. Stop it with `Ctrl+C`.

## Testing

Install the development dependencies and run the offline checks:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
```

The default test run uses model and storage doubles. It requires no API key, downloads
no embedding weights, and skips the database integration test. Interface tests cover
example questions, streamed answers and sources, empty input, and backend failures
using test doubles rather than live services.

With the Docker services running, test database persistence and conversation recovery:

```bash
POLICYDESK_INTEGRATION=1 python -m pytest -k database -q
```

In PowerShell, set `$env:POLICYDESK_INTEGRATION="1"` before running pytest.
Integration tests use unique `policydesk_test_*` namespaces and test-only models, so
they do not invoke paid Qwen inference or modify the configured policy namespace.
To verify real model answers, use `ask` and `chat` with your configured API key.

## Service operations

```bash
docker compose stop
docker compose start
docker compose logs --tail 30
```

Keep the Docker volumes to retain knowledge bases and conversations. Existing
installations should retain their database, namespace, and Compose project settings
when relocating the application. A new installation uses the PolicyDesk defaults.

PolicyDesk is a small internal application with CLI and local web interfaces. Session names separate histories but
do not authenticate users; the supplied database services bind to localhost. Policy
updates use new namespaces rather than incremental updates or partial-build repair.
