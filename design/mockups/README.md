# PolicyDesk front-end mockups

Static design proposals for the Streamlit app. Open any `.html` file directly in a
browser; they need no server, network access, or Python. The content is sample data.

| File | Direction | Reference products | Theme |
| --- | --- | --- | --- |
| `a_evidence_workspace.html` | Three panes: document library, questions, evidence panel | kotaemon (evidence panel with relevance scores) | Dark |
| `b_answer_engine.html` | Minimal search page; source cards before the answer; library in a drawer | Perplexity (source strip, phase indicator) | Dark, low-noise |
| `c_help_center.html` | Light employee portal with Ask / Documents tabs and a status table | Glean (cited HR answers), RAGFlow (document status list) | Light |

All three use only data PolicyDesk already returns: file name, page, content type,
reranker score, chunk count, upload time, and skipped figures. None requires a change
to retrieval or prompts. Things that would need extra work are listed below.

## What each needs in Streamlit

- **A:** `st.columns` for three panes and custom CSS. The thread shows earlier
  questions from this browser session; each question is still answered on its own.
  The low-relevance note is computed from the reranker score in the front end.
- **B:** a centered column, `st.status` for "searching" and "writing" phases, source
  cards rendered with HTML, and the library in the sidebar or a dialog. The "wrong
  sources" button and suggested questions are optional; suggestions would be a fixed
  list unless generated by the model.
- **C:** `st.tabs` for Ask and Documents, a document table built from columns, and a
  light theme in `.streamlit/config.toml`.

## Not shown, because the back end does not provide it yet

- Inline citation markers such as `[1]` inside the answer text (needs a prompt change).
- Section headings for each excerpt (needs headings stored at ingestion).
- A parsing percentage (ingestion runs as one step; the UI can only show "parsing").
